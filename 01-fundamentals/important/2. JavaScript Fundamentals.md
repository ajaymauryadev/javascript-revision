What is JavaScript?

JavaScript is a programming language used to add logic and interactivity to web applications.

It can run in the browser as well as on the server using environments like Node.js.

Simple Example

```js
let name = "Ajay";
```

console.log("Hello " + name);

Example: Here, JavaScript stores a value in name and prints it to the console.

## What are Data Types in JavaScript?

A data type defines what kind of value a variable can store in JavaScript.

### 2. 🔥🔥🔥 What are the different data types in JavaScript?

JavaScript data types are divided into two categories:

1. **Primitive Data Types**
2. **Non-Primitive Data Types**

### Primitive Data Types

JavaScript has **7 primitive data types**:

- **String** — text
- **Number** — numbers
- **BigInt** — very large integers
- **Boolean** — `true` or `false`
- **Undefined** — variable declared but no value assigned
- **Null** — intentional empty value
- **Symbol** — unique value

### Non-Primitive Data Types

The main non-primitive data types are:

- **Object**
- **Array**
- **Function**

### 3. 🔥🔥🔥 What are Primitive and Non-Primitive Data Types?

**Primitive data types** store a single value directly.

**Non-primitive data types** store collections or more complex data and are handled through references.

### Simple Example

```js
// Primitive
let name = "Ajay";
let age = 25;

// Non-Primitive
let person = {
  name: "Ajay",
  age: 25,
};

let skills = ["JavaScript", "React"];

function greet() {
  console.log("Hello");
}
```

### 4. 🔥🔥🔥 Difference between Primitive and Reference Types?

| Primitive                         | Reference                         |
| --------------------------------- | --------------------------------- |
| Stores a single value             | Stores a reference to the data    |
| Copied by value                   | Copied by reference               |
| Examples: String, Number, Boolean | Examples: Object, Array, Function |

### Simple Example

```js
// Primitive → copied by value
let a = 10;
let b = a;

b = 20;

console.log(a); // 10
console.log(b); // 20
```

```js
// Reference → copied by reference
let obj1 = { name: "Ajay" };
let obj2 = obj1;

obj2.name = "Rahul";

console.log(obj1.name); // Rahul
console.log(obj2.name); // Rahul
```

**Remember:**
**Primitive → value is copied**
**Reference → reference is copied**

## What is a Variable?

A variable is a named container used to store a value in JavaScript.

### Simple Example

```js
let name = "Ajay";
let age = 25;
```

Here, `name` stores `"Ajay"` and `age` stores `25`.

## 🔥🔥🔥 Difference between `var`, `let`, and `const`?

`var`, `let`, and `const` are keywords used to declare variables in JavaScript.

| Feature       | `var`          | `let`       | `const`         |
| ------------- | -------------- | ----------- | --------------- |
| Scope         | Function scope | Block scope | Block scope     |
| Redeclaration | Allowed        | Not allowed | Not allowed     |
| Reassignment  | Allowed        | Allowed     | Not allowed     |
| Hoisting      | Yes            | Yes         | Yes, but in TDZ |

### Simple Example

```js
var a = 10;
var a = 20; // Allowed

let b = 10;
b = 20; // Allowed

const c = 10;
// c = 20; // Error
```

**Remember:**

- `var` → function scoped, can redeclare and reassign
- `let` → block scoped, can reassign but cannot redeclare
- `const` → block scoped, cannot reassign or redeclare

## What is Hoisting?

Hoisting is JavaScript's behavior where variable and function declarations are processed before the code is executed.

This allows some variables and functions to be used before their declaration in the code.

### Simple Example

```js
console.log(a); // undefined

var a = 10;
```

Here, the declaration of `a` is hoisted, but its value `10` is assigned only when the code reaches `a = 10`.

### Function Example

```js
greet(); // Hello

function greet() {
  console.log("Hello");
}
```

**Remember:**

**Hoisting → declarations are processed before execution.**

<!-- ================== -->

## 🔥🔥🔥 How does hoisting work with `var`, `let`, and `const`?

All three — `var`, `let`, and `const` — are hoisted, but they behave differently when we try to access them before their declaration.

- **`var`** → hoisted and initialized with `undefined`.
- **`let`** → hoisted but not initialized. It stays in the **TDZ** until the declaration is reached.
- **`const`** → hoisted but not initialized. It also stays in the **TDZ** until the declaration is reached.

### Simple Example

```js
// var
console.log(a); // undefined
var a = 10;

// let
console.log(b); // ReferenceError
let b = 20;

// const
console.log(c); // ReferenceError
const c = 30;
```

**Remember:**

`var` → hoisted → `undefined`

`let` → hoisted → TDZ → error if accessed before declaration

`const` → hoisted → TDZ → error if accessed before declaration

## 🔥🔥🔥 What is the Temporal Dead Zone (TDZ)?

The **Temporal Dead Zone (TDZ)** is the time between entering a block and declaring a `let` or `const` variable, where the variable cannot be accessed.

If you try to access the variable during this time, JavaScript gives a **ReferenceError**.

### Simple Example

```js
console.log(a); // ReferenceError

let a = 10;
```

Here, `a` is in the **TDZ** from the beginning of the block until the line where `a` is declared.

**Remember:**

**TDZ → `let` and `const` → cannot access before declaration.**

## What is Scope?

Scope defines where a variable can be accessed in JavaScript.

### 1. 🔥🔥🔥 What is Scope?

Scope determines **where a variable is accessible** in the code.

### Simple Example

```js
let name = "Ajay";

function greet() {
  console.log(name);
}

greet(); // Ajay
```

Here, `name` can be accessed inside `greet()` because it is available in that scope.

---

### 2. 🔥🔥🔥 What is Global Scope?

A variable has **global scope** when it is declared outside all functions and blocks.

It can be accessed from different parts of the program.

### Simple Example

```js
let name = "Ajay";

function greet() {
  console.log(name);
}

greet(); // Ajay
```

Here, `name` has global scope.

---

### 3. 🔥🔥🔥 What is Function Scope?

A variable has **function scope** when it is declared inside a function and can be accessed only within that function.

### Simple Example

```js
function greet() {
  var name = "Ajay";

  console.log(name); // Ajay
}

greet();

console.log(name); // Error
```

Here, `name` is available only inside `greet()`.

---

### 4. 🔥🔥🔥 What is Block Scope?

A variable has **block scope** when it is declared with `let` or `const` inside a block `{ }`.

It can be accessed only inside that block.

### Simple Example

```js
if (true) {
  let name = "Ajay";

  console.log(name); // Ajay
}

console.log(name); // Error
```

Here, `name` is available only inside the `if` block.

---

### 5. 🔥🔥🔥 What is Lexical Scope?

Lexical scope means a function can access variables from the place where the function is **written in the code**.

### Simple Example

```js
let name = "Ajay";

function outer() {
  function inner() {
    console.log(name);
  }

  inner();
}

outer(); // Ajay
```

Here, `inner()` can access `name` because of where `inner()` is written.

---

### 6. 🔥🔥🔥 What is the Scope Chain?

The scope chain is the process JavaScript uses to find a variable by looking in the **current scope first**, then moving to its outer scope until it finds the variable.

### Simple Example

```js
let name = "Ajay";

function outer() {
  let age = 25;

  function inner() {
    console.log(age);
    console.log(name);
  }

  inner();
}

outer();
```

Here, `inner()` first looks for variables inside itself. If it cannot find them, it looks in `outer()`, and then in the global scope.

**Remember:**

**Scope Chain → Current Scope → Outer Scope → Global Scope**

## 🔥🔥 What is Strict Mode?

Strict mode is a JavaScript mode that makes the code **stricter** and helps catch common mistakes by throwing errors for certain unsafe behaviors.

**Remember:**

**Strict Mode → `"use strict"` → catches common mistakes with errors.**

## 🔥🔥🔥 Difference between `==` and `===`?

`==` and `===` are comparison operators used to compare values in JavaScript.

- `==` → compares values after **type conversion** if needed.
- `===` → compares **value and data type** without type conversion.

### Simple Example

```js
console.log(5 == "5"); // true
console.log(5 === "5"); // false
```

Here, `==` converts `"5"` to a number before comparing.

`===` does not convert the value, so `5` and `"5"` are different because their data types are different.

### Quick Difference

| `==`                        | `===`                   |
| --------------------------- | ----------------------- |
| Loose equality              | Strict equality         |
| Can perform type conversion | No type conversion      |
| Compares after conversion   | Compares value and type |

**Remember:**

`==` → value after conversion

`===` → value + type

## 🔥🔥🔥 What is Type Coercion?

Type coercion is the automatic conversion of a value from one data type to another by JavaScript.

### Simple Example

```js
console.log("5" + 2); // "52"
console.log("5" - 2); // 3
```

Here, JavaScript automatically converts the values to make the operation work.

**Remember:**

**Type Coercion → JavaScript automatically changes a value's data type when needed.**

## 🔥🔥🔥 What are Truthy and Falsy Values?

**Truthy values** are values that JavaScript treats as `true` in a condition.

**Falsy values** are values that JavaScript treats as `false` in a condition.

### Falsy Values

JavaScript has only these **7 falsy values**:

```js
false;
0 - 0;
0n;
("");
null;
undefined;
NaN;
```

Correction: JavaScript has **8 falsy values**:

```js
false;
0 - 0;
0n;
("");
null;
undefined;
NaN;
```

### Simple Example

```js
if ("Ajay") {
  console.log("Truthy");
}

if (0) {
  console.log("Falsy");
}
```

Here, `"Ajay"` is truthy, so the first condition runs.

`0` is falsy, so the second condition does not run.

**Remember:**

**Truthy → treated as `true`**

**Falsy → treated as `false`**

## 🔥🔥🔥 Difference between `null` and `undefined`?

`null` and `undefined` both represent the absence of a value, but they are used differently.

- `undefined` → a variable has been declared but no value has been assigned.
- `null` → we intentionally assign an empty value.

### Simple Example

```js
let a;
console.log(a); // undefined

let b = null;
console.log(b); // null
```

Here, `a` is `undefined` because no value was assigned.

`b` is `null` because we intentionally set it to an empty value.

| `undefined`                  | `null`                                |
| ---------------------------- | ------------------------------------- |
| Value is not assigned        | Empty value is assigned intentionally |
| Usually occurs automatically | Usually assigned manually             |

**Remember:**

`undefined` → **no value assigned**

`null` → **intentionally empty**

## What is `NaN`?

`NaN` stands for **Not-a-Number**. It is a special value that represents a result that is not a valid number.

### 1. 🔥🔥🔥 What is `NaN`?

`NaN` occurs when a mathematical operation cannot produce a valid number.

### Simple Example

```js
let result = "hello" - 5;

console.log(result); // NaN
```

Here, `"hello" - 5` cannot produce a valid number, so JavaScript returns `NaN`.

**Remember:**

**`NaN` → Not-a-Number → invalid numeric result**

---

### 2. 🔥🔥 What does `typeof` do?

`typeof` is an operator used to check the **data type of a value**.

### Simple Example

```js
console.log(typeof "Ajay"); // "string"
console.log(typeof 25); // "number"
console.log(typeof true); // "boolean"
```

**Remember:**

**`typeof` → tells the data type of a value**

---

### 3. 🔥🔥 What is `typeof null` and why?

`typeof null` returns `"object"`.

```js
console.log(typeof null); // "object"
```

This is a **historical mistake in JavaScript** that was kept for backward compatibility.

**Remember:**

**`typeof null` → `"object"` → historical JavaScript bug**

---

### 4. 🔥🔥 What is `typeof NaN`?

`typeof NaN` returns `"number"` because `NaN` is a special value of the **Number** data type.

```js
console.log(typeof NaN); // "number"
```

**Remember:**

**`typeof NaN` → `"number"`**

## 🔥🔥 What is Implicit vs Explicit Type Conversion?

**Implicit type conversion** is when JavaScript automatically converts a value from one data type to another.

**Explicit type conversion** is when we manually convert a value from one data type to another.

### Simple Example

```js
// Implicit conversion
let result = "5" - 2;

console.log(result); // 3
```

Here, JavaScript automatically converts `"5"` from a string to a number.

```js
// Explicit conversion
let value = "5";

let result = Number(value);

console.log(result); // 5
```

Here, we manually convert `"5"` from a string to a number using `Number()`.

**Remember:**

**Implicit → JavaScript converts automatically**

**Explicit → We convert manually**

### 1. 🔥 What is Strict Equality?

Strict equality uses the `===` operator to compare **both value and data type**.

```js
console.log(5 === 5); // true
console.log(5 === "5"); // false
```

Here, `5` is a number and `"5"` is a string, so the result is `false`.

**Remember:**

**Strict equality (`===`) → value + type**

### 2. 🔥 What is Loose Equality?

Loose equality uses the `==` operator to compare values after **type conversion if needed**.

```js
console.log(5 == "5"); // true
```

Here, JavaScript converts `"5"` to a number before comparing.

**Remember:**

**Loose equality (`==`) → value after type conversion**

### 1. 🔥🔥 What is `Object.is()`?

`Object.is()` is a method used to check whether two values are **exactly the same**.

It is similar to `===`, but it handles a few special values differently.

### Simple Example

```js
console.log(Object.is(5, 5)); // true
console.log(Object.is(5, "5")); // false
```

**Remember:**

**`Object.is()` → checks whether two values are exactly the same**

### 2. 🔥🔥 Difference between `Object.is()` and `===`?

Both compare values without type conversion, but they behave differently for `NaN` and `-0`.

```js
console.log(NaN === NaN); // false
console.log(Object.is(NaN, NaN)); // true

console.log(0 === -0); // true
console.log(Object.is(0, -0)); // false
```

| `===`                   | `Object.is()`                  |
| ----------------------- | ------------------------------ |
| `NaN === NaN` → `false` | `Object.is(NaN, NaN)` → `true` |
| `0 === -0` → `true`     | `Object.is(0, -0)` → `false`   |

**Remember:**

**`Object.is()` is almost like `===`, except for `NaN` and `-0`.**
