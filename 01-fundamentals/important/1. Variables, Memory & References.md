### 🔥🔥🔥 What is the difference between Value and Reference?(pass by value & referece)

**Pass by value** means a copy of the value is given to another variable. Changing one variable does not change the other.

**Pass by reference** means a reference to the same object is given to another variable. Changing the object through one variable also affects the other.

### Simple Example

```js
// Value
let a = 10;
let b = a;

b = 20;

console.log(a); // 10
console.log(b); // 20
```

Here, `b` gets a copy of the value of `a`.

```js
// Reference
let obj1 = { name: "Ajay" };
let obj2 = obj1;

obj2.name = "Rahul";

console.log(obj1.name); // Rahul
console.log(obj2.name); // Rahul
```

Here, both `obj1` and `obj2` refer to the same object.

**Remember:**

**Value → copy of the value**

**Reference → reference to the same object**

### 🔥🔥🔥 Is JavaScript Pass-by-Value or Pass-by-Reference?

JavaScript is **pass-by-value**.

When an object is passed to a function, the **value being passed is a reference to that object**. That is why changes to the object's properties can affect the original object.

### Simple Example

```js
let person = {
  name: "Ajay",
};

function changeName(obj) {
  obj.name = "Rahul";
}

changeName(person);

console.log(person.name); // Rahul
```

Here, JavaScript passes the **reference value** of the object by value.

**Remember:**

**JavaScript → always pass-by-value**

**Object → the value being passed is a reference to the object**

### 🔥🔥🔥 How are objects passed to functions?

Objects are passed to functions **by value**, where the value passed is a **reference to the same object**.

So, if we change a property inside the function, the original object is also changed.

### Simple Example

```js
let person = {
  name: "Ajay",
};

function changeName(obj) {
  obj.name = "Rahul";
}

changeName(person);

console.log(person.name); // Rahul
```

Here, `obj` and `person` refer to the **same object**, so changing `obj.name` also changes `person.name`.

**Remember:**

**Object → reference value is passed by value → same object can be modified**

### 1. 🔥🔥🔥 Why can a `const` object still be modified?

`const` prevents the variable from being **reassigned**, but it does not prevent the object's **properties from being changed**.

### Simple Example

```js
const person = {
  name: "Ajay",
};

person.name = "Rahul"; // Allowed

console.log(person.name); // Rahul
```

But you cannot assign a completely new object to `person`.

```js
person = { name: "Amit" }; // Error
```

**Remember:**

**`const` → cannot reassign the variable, but the object's properties can be changed.**

### 2. 🔥🔥 What happens when you assign one object to another variable?

Both variables point to the **same object** in memory.

### Simple Example

```js
let obj1 = {
  name: "Ajay",
};

let obj2 = obj1;

obj2.name = "Rahul";

console.log(obj1.name); // Rahul
console.log(obj2.name); // Rahul
```

Here, `obj2 = obj1` does not create a new object. Both refer to the same object.

**Remember:**

**Object assignment → both variables refer to the same object.**

---

### 3. 🔥🔥 What is Object Reference?

An object reference is the **reference that points to an object in memory**.

When an object is assigned to another variable, the reference to the same object is copied.

### Simple Example

```js
let person1 = {
  name: "Ajay",
};

let person2 = person1;

console.log(person1 === person2); // true
```

Here, both `person1` and `person2` refer to the same object.

**Remember:**

**Object reference → points to the object in memory.**

### 1. 🔥🔥 What is Shallow Copy?

A **shallow copy** creates a new object, but nested objects are still shared between the original and copied object.

### Simple Example

```js
let original = {
  name: "Ajay",
  address: {
    city: "Delhi",
  },
};

let copy = { ...original };

copy.name = "Rahul";
copy.address.city = "Mumbai";

console.log(original.name); // Ajay
console.log(original.address.city); // Mumbai
```

Here, `copy` is a new object, but `address` is still shared.

**Remember:**

**Shallow copy → new outer object, nested objects are shared.**

---

### 2. 🔥🔥🔥 What is Deep Copy?

A **deep copy** creates a completely independent copy of an object, including its nested objects.

### Simple Example

```js
let original = {
  name: "Ajay",
  address: {
    city: "Delhi",
  },
};

let copy = structuredClone(original);

copy.address.city = "Mumbai";

console.log(original.address.city); // Delhi
console.log(copy.address.city); // Mumbai
```

Here, `copy` and `original` have completely separate nested objects.

**Remember:**

**Deep copy → completely independent copy, including nested objects.**

### 1. 🔥🔥🔥 How do you clone an object?

You can clone an object using the **spread operator (`...`)** for a shallow copy or **`structuredClone()`** for a deep copy.

### Simple Example

```js
// Shallow copy
let original = {
  name: "Ajay",
  age: 25,
};

let copy = { ...original };

console.log(copy);
```

For a deep copy:

```js
let original = {
  name: "Ajay",
  address: {
    city: "Delhi",
  },
};

let copy = structuredClone(original);
```

**Remember:**

**`...` → shallow copy**

**`structuredClone()` → deep copy**

---

### 2. 🔥🔥 What is `structuredClone()`?

`structuredClone()` is a built-in JavaScript method used to create a **deep copy** of a value.

It creates a new object with its own copies of nested objects.

### Simple Example

```js
let original = {
  name: "Ajay",
  address: {
    city: "Delhi",
  },
};

let copy = structuredClone(original);

copy.address.city = "Mumbai";

console.log(original.address.city); // Delhi
console.log(copy.address.city); // Mumbai
```

Here, changing the nested object in `copy` does not affect `original`.

**Remember:**

**`structuredClone()` → creates a completely independent deep copy.**

### 🔥🔥 Difference between Shallow Copy and Deep Copy?

| Shallow Copy                                      | Deep Copy                             |
| ------------------------------------------------- | ------------------------------------- |
| Creates a new outer object                        | Creates a completely independent copy |
| Nested objects are shared                         | Nested objects are also copied        |
| Changes to nested objects can affect the original | Changes do not affect the original    |
| Example: `{ ...obj }`                             | Example: `structuredClone(obj)`       |

### Simple Example

```js
let original = {
  name: "Ajay",
  address: {
    city: "Delhi",
  },
};

// Shallow Copy
let shallow = { ...original };

// Deep Copy
let deep = structuredClone(original);

shallow.address.city = "Mumbai";

console.log(original.address.city); // Mumbai

deep.address.city = "Pune";

console.log(original.address.city); // Mumbai
```

**Remember:**

**Shallow copy → outer object new, nested objects shared**

**Deep copy → everything copied, no shared nested objects**

### 1. 🔥🔥 What is `Object.freeze()`?

`Object.freeze()` makes an object **completely unchangeable**.

You cannot **add, remove, or modify** its properties.

### Simple Example

```js
let person = {
  name: "Ajay",
  age: 25,
};

Object.freeze(person);

person.name = "Rahul"; // No change
person.city = "Delhi"; // No change
delete person.age; // No change

console.log(person);
// { name: "Ajay", age: 25 }
```

**Remember:**

**`Object.freeze()` → cannot add, delete, or modify properties.**

---

### 2. 🔥 What is `Object.seal()`?

`Object.seal()` prevents an object from having properties **added or deleted**, but existing properties can still be modified.

### Simple Example

```js
let person = {
  name: "Ajay",
  age: 25,
};

Object.seal(person);

person.name = "Rahul"; // Allowed
person.city = "Delhi"; // No change
delete person.age; // No change

console.log(person);
// { name: "Rahul", age: 25 }
```

**Remember:**

**`Object.seal()` → cannot add or delete, but can modify existing properties.**

---

### 3. 🔥🔥 Difference between `Object.freeze()` and `Object.seal()`?

| `Object.freeze()`        | `Object.seal()`                |
| ------------------------ | ------------------------------ |
| Cannot add properties    | Cannot add properties          |
| Cannot delete properties | Cannot delete properties       |
| Cannot modify properties | Can modify existing properties |

**Remember:**

**Freeze → Nothing can be changed**

**Seal → Add/Delete blocked, Modify allowed**

### 🔥🔥 What is Immutability?

Immutability means **an existing value or object cannot be changed after it is created**.

Instead of changing the original value, we create a **new value or object** with the required changes.

### Simple Example

```js
let person = {
  name: "Ajay",
  age: 25,
};

// Create a new object instead of changing the original
let updatedPerson = {
  ...person,
  age: 26,
};

console.log(person.age); // 25
console.log(updatedPerson.age); // 26
```

Here, the original `person` object is not changed. A new object is created with the updated value.

**Remember:**

**Immutability → don't change the original; create a new value instead.**

### 🔥 What is Garbage Collection?

Garbage collection is the process by which JavaScript **automatically removes objects from memory that are no longer reachable or needed**.

### Simple Example

```js
let person = {
  name: "Ajay",
};

person = null;
```

Here, the object `{ name: "Ajay" }` is no longer reachable, so JavaScript's garbage collector can remove it from memory.

**Remember:**

# **Garbage Collection → automatically removes unused objects from memory.**
